普通读取会让 Reactive Scope“关注”这个 Signal；而 `peek()` 只是“偷看”当前值，不会让 Reactive Scope 关注它。

### 举例

点击以下组件的第一个按钮可以改变 `count1` 的值，但是 `"Totle = {total}"` 的文本信息并没有变（验证了 peek 的非响应式读取）。而点击第二个按钮时，文本信息则会立即变化（因为 total 响应式依赖 count2 了）。

```rust
#[component]
fn TestPeek() -> Element {
    let mut count1 = use_signal(|| 1);
    let mut count2 = use_signal(|| 100);

    let total = use_memo(move || {
        // peek() 只读取 count1 的当前值，不会订阅 count1 的变化。
        let value1 = *count1.peek();

        // 普通读取会建立响应式依赖。
        // 因此 count2 变化时，这个 memo 会重新计算。
        let value2 = count2();

        value1 + value2
    });

    rsx! {
        button { onclick: move |_| count1 += 1, "count1 = ({count1})" }
        button { onclick: move |_| count2 += 100, "count2 = ({count2})" }
        "Totle = {total}"
    }
}
```

### 对比

只有调用了 `read()` 方法的 Signal 才会注册依赖

| **语法写法**   | **实际调用的方法**               | **是否注册依赖？** | **适合场景**                                              |
| -------------- | -------------------------------- | ------------------ | --------------------------------------------------------- |
| `count.read()` | `read()`                         | **是**             | 显式借用（返回 `Ref<T>`，不发生内存拷贝，适合复杂类型）。 |
| **`count()`**  | `read().clone()`                 | **是**             | **最常用**。适合 `Copy` 或简单类型，代码最清爽。          |
| `*count`       | `Deref` $\rightarrow$ `read()`   | **是**             | 解引用语法。                                              |
| `"{count}"`    | `Display` $\rightarrow$ `read()` | **是**             | 在 `rsx!` 格式化字符串中直接插入，隐式调用 `read()`。     |
| `count.peek()` | `peek()`                         | ❌                 | 静默读取，**唯一主动跳过**依赖注册的 API。                |
